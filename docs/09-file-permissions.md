# Урок 9: права файлов `custom_files` (IB / SB)

## Зачем нужна политика

На Windows/NTFS bind-mount может предоставлять каталогам и файлам права `0777`. Ранее `cp -a` (IB) и `rsync -a` (SB) без нормализации переносили эти биты в создаваемый SquashFS. Механизм `system/overlay_permissions.sh` **одинаков** для Image Builder и Source Builder и применяется **только к временной копии** `custom_files/<профиль>`, до `make image` / синхронизации в `files/`. Исходные файлы на хосте не меняются. В Source Builder ошибочная политика останавливает сборку **до** удаления ранее управляемых файлов persistent workdir.

| Назначение пути внутри будущего rootfs | Режим по умолчанию |
|---|---|
| Обычные файлы (включая `.sh` вне исполняемых путей) | `0644` |
| Обычные каталоги | `0755` |
| `/root` | `0750` |
| `/root/.ssh/`, `/etc/dropbear/`, `/etc/ssl/private/`, `/etc/wireguard/` и их вложенные каталоги | `0700` |
| Личные SSH-ключи, `authorized_keys`, Dropbear host keys, `/etc/shadow`, `/etc/gshadow`, PPP secrets, файлы в закрытых каталогах | `0600` |
| Публичные ключи `/root/.ssh/*.pub` | `0644` |
| `/etc/uci-defaults/*`, `/etc/hotplug.d/*` | `0644` — OpenWrt подключает эти скрипты через shell (`.`); executable bit не обязателен |
| `/etc/init.d/*`, `/etc/rc.button/*`, `/etc/rc.local`, программы в `/bin`, `/sbin`, `/usr/bin`, `/usr/sbin` | `0755` |

**Не определяем исполняемость по расширению `.sh`**: в OpenWrt есть как запускаемые, так и подключаемые скрипты. Не нормализуем целиком файловую систему OpenWrt или содержимое бинарных пакетов (`.apk`/`.ipk`). Штатные права upstream и пакетов остаются за их сборочными инструментами.

## Ручные исключения

Если нужен другой режим, создай текстовый файл `custom_files/<профиль>/.routerfw-permissions` (UTF-8, LF/CRLF) со строками вида:

```text
# MODE /absolute/path/in/router/rootfs
0600 /etc/config/my-private-service
0750 /etc/my-private-service
0755 /opt/my-app/launch.sh
0640 /etc/routerfw/with space.txt
```

Указывается **точный существующий путь** в `custom_files`; можно писать также без начального `/`. Режим — строго четыре восьмеричные цифры (`0644`, `0755` и т. д.), без special bits и world-write. Каталоги должны быть доступны владельцу для чтения и входа, обычные файлы — для чтения. Дубли, `..`, ссылки, несуществующие пути и некорректные режимы приводят к ошибке сборки, а не к молчаливому игнорированию. Сам `.routerfw-permissions`, как и `hooks.sh`, не попадает в firmware. Не следует использовать `0777`, даже «для удобства».

* Изменение только режима при неизменном содержимом файла тоже применяется при следующей инкрементальной сборке SB.
* Не создавай секреты в публично распространяемой прошивке: `0600` предотвращает доступ непривилегированных процессов, **но не скрывает секрет от человека, получившего файл образа**.
* Симлинки, FIFO, сокеты и device nodes в обычном `custom_files` отвергаются. Для нестандартных файлов используй корректно оформленный пакет или обоснованную специальную процедуру.
* Скрипт `hooks.sh` не является частью файлового overlay и имеет отдельный жизненный цикл. Изменения, которые hooks делают непосредственно в `files/`, **не нормализуются этой политикой**; ответственность за их права несёт hook.
* В итоговой прошивке ожидаемый владелец обычных файлов `root:root` устанавливается штатными механизмами упаковки OpenWrt; этот модуль управляет именно битами режима, не выполняет `chown`.

## Проверка

После сборки проверь права и содержимое непосредственно в SquashFS внутри `sysupgrade.itb`: тестовый `/etc/routerfw/overlay-probe.txt` должен иметь `0644`, каталог — `0755`, `/etc/uci-defaults/99-permissions.sh` — `0644`. Для проверки SB используй тот же persistent Docker volume (в том числе повторные ON → OFF и v1 → v2). Старые прошивки автоматически не изменяются: требуется новая сборка.

Offline-регрессии: `python3 -B -m unittest tests.test_overlay_permissions` и `bash tests/test_src_builder_lifecycle.sh`. Публикаторы `_packer.sh` и `_packer.bat` включают общий модуль и эту документацию в `_unpacker`.
