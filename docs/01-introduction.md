# Урок 1: Знакомство с Универсальным Билдером

## Проблема: Своя прошивка — это сложно?

Наверняка вы хотели иметь прошивку для своего роутера, в которую уже встроены все ваши настройки, любимые программы и важные файлы? Не просто бэкап, который можно восстановить, а полноценный `.bin` файл для прошивки "с нуля", после которой роутер сразу готов к работе.

Многие, открыв официальные инструкции по сборке OpenWrt, откладывали эту идею со словами "не сегодня". Установка Linux, работа в командной строке, управление зависимостями — все это создает высокий порог входа.

**Универсальный Билдер был создан, чтобы решить именно эту проблему.**

## Философия Билдера: простота на Windows и Linux

Идея проекта — дать возможность собирать свои прошивки OpenWrt на Windows или Linux, не превращая хост в полноценную среду разработки OpenWrt. На Windows используется Batch-оболочка, на Linux — Bash; тяжёлая сборка выполняется в контейнерной среде.

*   **Почему Docker или Podman?**\
    Компиляторы и зависимости находятся внутри контейнера, а не устанавливаются вручную в основную ОС. Это изолирует большую часть build-инструментария и делает среду более предсказуемой. Полная воспроизводимость всё равно зависит от версии SDK/исходников, репозиториев, пакетов и внешних источников.

*   **Почему `.bat` скрипты?**  
    Для максимальной простоты. Вам не нужно устанавливать Python, MSYS2 или другие инструменты в вашу систему. Скачали один файл, запустили — всё работает "из коробки". Это родной и понятный способ для Windows.

*   **Почему это лучше, чем делать по официальному мануалу?**  
    Билдер — это не замена, а **умная автоматизация** официальных инструментов OpenWrt. Он берет на себя всю сложную и рутинную работу:
    *   **Скорость:** Повторные сборки занимают 1-3 минуты благодаря мощной системе кэширования.
    *   **Удобство:** Дружелюбное меню вместо десятков команд в консоли.
    *   **Надёжность:** Для отдельных сетевых операций и стадий сборки предусмотрены повторные попытки. Vermagic hook может попытаться повысить совместимость kernel modules; при отсутствии hook существует узкий откат поддерживаемого Vermagic-состояния. Это не универсальное восстановление после любых ошибок или повреждения хранилища.

## Подготовка к работе

Для работы с Билдером вам понадобится всего две вещи:

1.  **Контейнерный runtime — Docker или Podman.** Выберите один из поддерживаемых вариантов и установите его для своей ОС.
    *   [Docker Desktop для Windows](https://docs.docker.com/desktop/install/windows-install/) — использует WSL2 backend.
    *   [Podman Desktop для Windows](https://podman-desktop.io/docs/installation/windows-install) — использует управляемую Linux-среду/WSL machine.
    *   [Установка Podman на Linux](https://podman.io/docs/installation). Docker Engine и Docker Compose также доступны для Linux по [официальной документации](https://docs.docker.com/engine/install/).
    *   Для Windows убедитесь, что выбранный runtime и Compose provider доступны из командной строки. В Bash под WSL routerFW также умеет использовать `docker.exe` / `podman.exe`, если нативная Linux-команда отсутствует.

>[Всегда свежий WSL напрямую от Microsoft](https://github.com/microsoft/WSL)

2.  **Сам Билдер:** на Windows скачайте `_unpacker.bat`, на Linux — `_unpacker.sh` из корневого README или раздела Releases. Поместите файл в пустую папку и запустите — он восстановит структуру проекта.

Готовые сборки (с форума, keeneticported и т.п.) — это вариант «поставил и забыл»: прошивка уже собрана, но изменить состав пакетов или встроить свои конфиги в образ нельзя. Билдер даёт полный контроль: вы собираете прошивку под себя — свои пакеты, настройки и обновления, когда нужно.

## Два режима работы

Билдер объединяет два подхода к сборке:

#### 1. Image Builder (Быстрый режим)

Это режим по умолчанию. Его можно сравнить со сборкой чемодана: вы берёте готовые "вещи" (скомпилированные пакеты) и аккуратно укладываете их вместе со своими настройками.
*   **Плюсы:** Очень быстро (повторная сборка ~2 минуты).
*   **Идеально для:** добавления программ, встраивания файлов конфигурации.

#### 2. Source Builder (Мощный режим)

Это можно сравнить с пошивом одежды с нуля. Процесс долгий, но вы контролируете каждый "стежок".
*   **Плюсы:** Полный контроль над прошивкой, включая ядро и драйверы.
*   **Идеально для:** глубоких изменений, которые невозможно сделать в быстром режиме.
